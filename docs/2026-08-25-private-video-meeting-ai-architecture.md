# 私有化 AI 视频会议系统架构基线

**日期**：2026-08-25  
**状态**：已确认 / 可进入 PoC 设计  
**范围**：单企业私有化部署；员工用 Windows/macOS Tauri 客户端；嘉宾可用浏览器或 Tauri；Linux 后续复用

本文是 grilling 后锁定的产品与架构基线。未列入的细节按文末「实现假定」处理，不挡 PoC。

## 1. 决策摘要

本系统不是实时 AI 会议助手，而是「企业私有会议 + 会后 AI 处理 + 跨会议知识库」。

### 1.1 已锁定约束

- 数据不进入第三方云。部署分两种：**无第三方出站** 的私有安装，以及可选的 **DMZ 嘉宾入站**。所谓离线不是「不能有任何入站」，而是模型/镜像可离线安装、业务与 AI 不调用第三方。
- 单企业、单租户，单会议不超过 50 人。
- 支持普通话、粤语和多语种；粤语目标为理解大意，不承诺逐字准确。
- 不要求端到端加密，服务器可以读取会议媒体并做会后处理。
- 会后处理，不要求实时转写或会中 AI 助手。
- **转写的权威音源是 LiveKit Egress 的独立参会人音轨**，不是客户端本地录音。
- **本地麦克风录音只存在于员工的 Tauri 客户端**：进会必须开始，允许暂停（审计记缺口），必须自动上传。浏览器没有本地录音。嘉宾任何一端都不做本地录音。
- 录音、转写、聊天、纪要、下载、知识库查询纳入企业审计。
- 媒体保留和知识保留是两套时钟，由管理员分别配置。
- 员工身份由企业现有 IdP 负责；会议网关只校验 token 并做会议内鉴权。每个现场一种员工登录方式，由身份系统保证。
- 会议媒体层 **锁死 LiveKit**。Jitsi 若出现，只作为「整套会议产品替换」，不为它保持可替换抽象。
- 技术实现见 `docs/2026-08-25-tech-stack.md`（Gin、Dapr、PostgreSQL、Vespa）。

### 1.2 核心选型

| 层 | 首选 | 备选/说明 |
|---|---|---|
| 会议媒体 | LiveKit Server | 不保持 Jitsi 适配层 |
| 会议 UI | Vite + React + LiveKit components | 与员工/嘉宾共用一份 SPA；壳参考 Meetily |
| 员工桌面端 | Tauri 2 | Win/macOS 首发；承担本地录音上传 |
| 嘉宾入口 | 浏览器（主）或 Tauri | Tauri 对嘉宾只提供开会，不启用本地录音 |
| 企业网关 | Go + Gin | 只消费企业身份 token，不自建 IdP |
| 会后编排 | Dapr Workflow + Pub/Sub | 现场已有 Dapr；PostgreSQL 仍是任务权威状态 |
| 服务端录制 | LiveKit Egress | 房间画面（含共享）+ 房间混音 + 独立音轨 |
| 对象存储 | MinIO 或企业 S3 | 离线安装使用 MinIO |
| 关系数据 | PostgreSQL | 业务、审计、ACL 的唯一权威源 |
| 知识检索 | Vespa | 带 ACL 字段的检索副本；现场已有集群 |
| 中文 ASR | FunASR | PoC 用真实样本对比 WhisperX/faster-whisper |
| 混音说话人分离 | CAM++ / pyannote | 仅独立音轨不可用且无该人员工本地备份时的降级 |
| 会议智能 | 私有 Qwen + vLLM/Ollama | CPU 环境允许队列延迟 |

生产交付包只含已获得商业授权（或可商用协议）的模型与镜像。PoC 可用研究权重做评测，不得打进交付包。

## 2. 系统边界

### 2.1 进入企业服务器的数据

- 员工账号、嘉宾邮箱身份、角色和身份映射。
- 会议元数据、参会人列表、房间密码哈希、聊天消息。
- 服务端房间混音、独立参会人音轨、房间画面（含屏幕共享，供回看）。
- 员工 Tauri 上传的本地麦克风备份。
- 转写片段、语言、时间戳、模型版本、音源标记（`egress` / `local_fallback`）。
- 纪要、决策、待办、风险、引用来源及人工修订事件。
- 向量索引和知识库问答审计记录。
- 进会录音确认、破窗申请/批准、下载事件。

### 2.2 明确不做（含 v1 不做）

- 第三方云端转写、第三方云端摘要、第三方邮件 SaaS。
- 面向多租户 SaaS 的计费和租户管理。
- 移动端原生客户端。
- 会议进行中的实时字幕和实时 AI 助手。
- 依赖混音 diarization 才能识别正常参会人。
- 电话 / SIP / 匿名无标识接入。
- 等候室。
- 日历同步（Outlook / Google / 飞书）。
- 待办与 Jira / 飞书任务等外部系统双向同步。
- 场外混音/录像文件导入转写。
- 视觉 AI（共享文档 OCR、会中画面理解）。
- 为 Jitsi 预留媒体抽象。

## 3. 总体架构

```text
Employee Tauri (enterprise IdP token)
  |-- meeting UI (Vite SPA + LiveKit components)
  |-- mic/camera/screen -> LiveKit
  |-- local mic recording: encrypted spool + resumable upload
  '-- audit event client

Guest Browser or Guest Tauri
  |-- meeting UI (same SPA)
  |-- mic/camera/screen -> LiveKit
  |-- NO local recording
  '-- recording acknowledgement

          |
          v
Enterprise Gateway / API (Go + Gin)
  |-- Validate enterprise identity token + meeting RBAC
  |-- Meeting, invite, password, lock/kick
  |-- Guest email bind (SMTP OTP or in-meeting code)
  |-- Recording upload API (employees only)
  |-- Transcript / artifact / download API
  '-- Knowledge query API (ACL-first -> Vespa)
          |
          +--> LiveKit Server (+ optional DMZ: HTTPS invite + TURN + SFU ingest)
          |      '-- LiveKit Egress (audio tracks + room composite video)
          |
          +--> PostgreSQL
          +--> MinIO/S3
          +--> Dapr Workflow + Pub/Sub
          +--> Vespa (search replica)
          +--> optional enterprise SMTP
          |
          '-- Post-processing workers (Python)
                 |-- media normalizer
                 |-- FunASR / WhisperX ASR
                 |-- artifact extraction LLM
                 '-- embedding and Vespa indexer
```

### 3.1 会议媒体路径

1. 员工用企业 IdP 登录后，Tauri 携带企业 token 调会议网关；网关校验 token，不自建登录。
2. 嘉宾用邀请链接 + 房间密码进入会中 UI；API 签发 **嘉宾** LiveKit JWT。已登录员工若用同一链接加入，仍按员工身份计。
3. 进会前全员必须确认：本会将被企业服务器录音、转写，并可能进入知识库。不确认不能进。文案须写明：员工暂停的是本机备份，不是服务端录制。
4. 客户端发布麦克风、摄像头和屏幕轨道。LiveKit 只做实时转发和房间事件。
5. 同一员工允许多端观看，但同一时刻只发布一路麦克风；后发麦的端成为音频源，前一端静音。本地录音只在正在发麦的那台员工 Tauri 上运行。
6. Egress 在会议结束时保存：独立参会人音轨、房间混音、房间画面（含共享）。画面供回看，**不送入 AI**。
7. 媒体写入对象存储，元数据写入 PostgreSQL。

### 3.2 说话人归属

主路径（正常会议）：

```text
LiveKit participant_id
  -> employee user_id  或  guest email identity（验证后）
  -> display_name snapshot（入会时）
  -> transcript segment speaker_display_name
```

- 员工：企业 `user_id`。
- 嘉宾：密码对了即可进音视频；会中先用当场填写的显示名和临时 ID。会后访问产物必须验证邮箱（SMTP OTP/魔法链接，或组织者出示的会中验证码）。验证后临时 ID 合并到该邮箱身份。
- 显示名在入会时快照，避免事后改名改写历史纪要。

独立音轨缺失时：

1. 若该人是员工且本地备份已上传并 checksum 确认，则 **仅该人** 改用本地文件做 ASR，片段标记 `source=local_fallback`。
2. 否则该人转写失败；不得改走房间混音 + diarization 顶上。
3. 整场 Egress 都没有时，会议进入 `MANUAL_REVIEW`。

CAM++/pyannote 只用于「确实只剩单一音频轨道」的降级。v1 无外部文件导入，也无电话/匿名参会，因此这不是主链路，也不是客户功能。

## 4. 会议生命周期与进会控制

### 4.1 创建

- 第一版只做 **即时会议**，不做日历。
- 创建时自动生成房间密码；组织者可复制、可重置（重置后旧密码立即失效）。
- 组织者可从企业目录勾选内部参会人：这些人在 Tauri 会议列表里 **一键加入，不需要房间密码**。
- 可指定若干 **内部** 共同组织者，权限与创建者相同。嘉宾不能当组织者。
- 未勾选的员工仍可用嘉宾链接 + 密码加入；加入后识别为员工（必须走 Tauri、强制本地录音）。

### 4.2 员工与嘉宾入口

| | 员工 | 嘉宾 |
|---|---|---|
| 浏览器 | 拦截或跳转「打开 Tauri」，不能在浏览器开会 | 主入口 |
| Tauri | 必须；进会必须开始本地录音 | 可用；不启用本地录音 |
| 进会凭证 | 已邀请：列表一键进。未邀请：链接+密码 | 链接+密码即可进会中 |
| 会后身份 | 企业账号 | 须验证邮箱 |

没有等候室。拿到链接和密码的人可以直接进，直到会议被锁定或结束。

### 4.3 会中控制

- 组织者/共同组织者可以踢人，可以 **锁定会议**（默认不锁）。
- 锁定后 **任何人** 不能新加入，包括员工一键加入和嘉宾链接，直到解锁。
- 组织者掉线不自动散会；锁/踢/会后分享仍由在线的共同组织者执行。

### 4.4 结束

- 组织者/共同组织者可「全员结束」。
- 连续 N 分钟（默认 10，管理员可配）无人在线则自动结束、停止 Egress、进入会后流水线。
- 不要在最后一个人离开的瞬间立刻结束（刷新或短暂断网会误杀）。

## 5. 本地录音自动上传（仅员工 Tauri）

本地录音是员工侧的合规备份：录的是 **自己的麦克风**，不是系统音频/loopback，也不是整场混音。它不是转写主音源，也不是用户可在进会前关掉的功能。

浏览器进会的人（嘉宾）没有这条链；审计记「此端无本地录音能力」即可。

### 5.1 客户端状态机

```text
IDLE
  -> RECORDING
  -> FINALIZING
  -> QUEUED
  -> UPLOADING
  -> VERIFYING
  -> ACKED
  -> PURGE_PENDING
  -> PURGED
```

用户可暂停：

```text
RECORDING -> PAUSED -> RECORDING
```

暂停必须写审计缺口。静音不是暂停：近端不说话时录音会话仍在。

失败路径：

```text
UPLOADING/VERIFYING -> RETRY_WAIT -> UPLOADING
任意上传失败        -> UPLOAD_FAILED（继续保留本地加密文件）
```

系统中断（崩溃、被杀进程、锁屏）按原失败/恢复路径处理，恢复后继续同一上传队列。

### 5.2 必须满足的行为

- 录音分块，并为每个分块保存 checksum。
- 服务器支持断点续传和幂等重试。
- 服务端合并后重新计算整文件 checksum。
- 未收到服务端确认前，客户端不能删除本地文件。
- 上传失败时保持本地加密副本，并显示可恢复状态。
- 服务端确认后根据管理员策略删除或保留本地副本。
- 录音开始、暂停、恢复、停止、上传、确认、删除都写审计事件。
- 客户端重启后能够恢复待上传队列。

### 5.3 本地安全

- 本地录音使用企业下发的设备密钥或会话密钥加密（这是设备落盘保护，不是端到端加密；服务端必须能解密以供审计回放和 `local_fallback` ASR）。
- 临时文件放在应用专属目录，不能使用公开共享目录。
- 本地副本有过期时间，不能无限期保留。
- 退出登录、设备注销和管理员吊销时停止后续上传。
- 不能把录音写入日志、崩溃报告或遥测。

## 6. 会后 AI 流水线

### 6.1 任务状态

```text
RECORDING_FINALIZED
  -> MEDIA_READY
  -> TRANSCRIBING
  -> TRANSCRIPT_READY
  -> EXTRACTING_ARTIFACTS
  -> INDEXING
  -> READY
```

任何阶段失败都进入 `RETRYABLE_ERROR` 或 `MANUAL_REVIEW`，不能静默生成不完整纪要。

### 6.2 转写输出

每个片段至少保存：

```json
{
  "meeting_id": "...",
  "track_id": "...",
  "speaker_user_id": "...",
  "speaker_display_name": "...",
  "language": "zh-CN",
  "start_ms": 1200,
  "end_ms": 5400,
  "text": "...",
  "asr_model": "...",
  "source": "egress",
  "confidence": null
}
```

- `source` 为 `egress` 或 `local_fallback`。
- `speaker_user_id` 在嘉宾未验证前可以是临时 ID，验证后回填合并。
- 置信度字段允许为空，不应伪造模型没有提供的概率。

### 6.3 纪要输出

大模型必须输出结构化结果，并保留来源：

```json
{
  "summary": "...",
  "decisions": [
    {"text": "...", "source_segment_ids": []}
  ],
  "action_items": [
    {
      "task": "...",
      "owner_user_id": "...",
      "deadline": null,
      "source_segment_ids": [],
      "source_message_ids": []
    }
  ],
  "risks": [],
  "open_questions": []
}
```

- 待办留在本系统，不对接外部任务系统。可导出文件。
- `owner_user_id` 只能是企业内部用户；不允许模型臆造负责人；嘉宾可写在任务描述里，不能作为系统负责人。
- **企业内部参会人** 可编辑 AI 纪要和待办；**嘉宾只读**。
- 原始转写和原始聊天不可覆盖，只能追加修订事件（谁、何时、改了什么）；AI 原稿保留。

聊天必须通过自己的 API 落库，不能只依赖 LiveKit 数据通道的短暂消息。

### 6.4 普通话、粤语、多语种

第一版不预设单一模型覆盖所有语言，采用评测后配置路由：

- 普通话：FunASR 主路线。
- 粤语和中英混合：FunASR 与 WhisperX/faster-whisper 对比后配置。
- 语言不确定：先做语言识别，再按会议或片段选择模型。

验收以「可理解大意」为主：主题、结论、待办、人名、日期和专有名词，而不是只比较 WER/CER。

## 7. 跨会议知识库

### 7.1 默认可见范围

- 默认：该场会的参会人（含已验证邮箱的嘉宾）+ 组织者。
- 组织者可把 **任意邮箱** 加成读者（会外嘉宾读者，须完成邮箱验证）。
- 嘉宾可以检索 **自己参加过或被分享到的会**，不能看其他会，不能当组织者。
- 向量块按「可访问的会议集合」在 **Vespa 查询条件里**过滤后再检索，不能先对全库检索再在回答阶段滤权限。PostgreSQL 保存 ACL 真相，Vespa 是带同样 ACL 字段的检索副本。

索引对象：纪要段落、决策和待办、带时间戳的转写片段、聊天消息窗口。录像不进向量索引。

每个向量块必须带 ACL 元数据：

```text
meeting_id
allowed_user_ids
allowed_guest_emails
source_type
source_id
timestamp
```

`department_ids` 不是默认授权维度（不做「同部门默认可搜」）。字段若保留，只作可选标注，不参与默认 ACL。

### 7.2 查询路径

```text
用户问题
  -> 身份（企业 token → 员工，或已验证嘉宾）
  -> 可访问会议集合（参加过 ∪ 被分享）
  -> Vespa：ACL 条件内的关键词/向量检索
  -> 原文片段和时间戳（PostgreSQL 可回源校验）
  -> 私有大模型生成回答
  -> 返回引用会议、日期和来源
```

### 7.3 产物权限与下载

房间录像（含屏幕共享画面）与转写/纪要 **同一套 ACL**：能看纪要就能在线回看录像。

有权查看的人可以下载音频、录像、转写；每次下载记审计。不做「只能在线、禁止下载」的防泄密播放。

### 7.4 保留

两套时钟，管理员分别配置：

1. **媒体保留**：独立音轨、混音、房间画面、员工本地备份。
2. **知识保留**：转写、纪要、决策、待办、向量块。

知识到期后必须删除对应向量，不能只删对象存储文件而留下可检索块。画面占用大，允许比音频更短的媒体时钟。

## 8. 权限和审计

### 8.1 角色

- `system_admin`：部署、模型、保留策略、IdP 选择、SMTP、DMZ 开关。 **默认不能看会议内容。**
- `audit_admin`：审计查询、导出日志、核对对象是否存在及 checksum。 **默认不能播放或下载会议内容。**
- `organizer` / 共同组织者：创建会议、锁/踢、邀请、会后白名单、结束会议。
- `participant`：内部参会人，可看可下载可改纪要（本场授权范围内）。
- `guest`：外部人，会中可参会；会后只读已授权会议。

破窗听会：一名 `audit_admin` 申请，另一名 `audit_admin` 或 `system_admin` 批准；有时限，到期收回；申请人不能批自己；申请、批准、访问全程审计。

### 8.2 审计事件

- 登录、登出、身份绑定、嘉宾邮箱验证（含会中验证码）。
- 加入/离开会议、锁定/解锁、踢人、重置房间密码。
- 进会前录音确认。
- 开始/停止/暂停/恢复本地录音（含缺口）。
- 本地录音上传和服务端确认。
- 查看、下载、删除录音/录像。
- 查看、修改、导出转写和纪要。
- 创建、修改、完成待办。
- 发起知识库查询。
- 修改保留策略、模型配置、破窗申请与批准。

审计日志只追加，不允许普通业务 API 修改或删除。

## 9. 部署模式

两种模式共享 API、数据库和 AI 工作流，差别在出站依赖、入站暴露和安装方式。

### 9.1 联网私有部署

- 会议媒体、模型请求和业务数据不调用第三方服务。
- 可经企业代理拉更新/镜像。
- 可开启 DMZ：邀请页 + TURN + SFU 入站，供公网嘉宾进入；媒体与 AI 仍只落在企业侧。
- 默认可配企业 SMTP；无 SMTP 时用复制链接 + 会中验证码。
- 默认关闭遥测。

### 9.2 无第三方出站 / 离线安装

交付物包括：

- 签名 Docker 镜像包。
- 签名、已授权的模型权重包。
- 数据库迁移包。
- 离线 Tauri 客户端安装包。
- GPU/CPU 兼容性检查脚本。
- 离线升级和回滚包。
- 可选 DMZ 入站配置说明（证书、TURN、防火墙）。

没有 DMZ 的物理隔离现场：外部嘉宾必须先进入可达网络（VPN/跳板/现场网络），产品不能隔空打进断网机房。

**PoC 不包含公网 DMZ。** PoC 在内网（含 VPN 后的嘉宾）验证链接+密码、邮箱/验证码绑定、员工走链接仍按员工计。DMZ 作为 v1 交付项。

## 10. PoC 验收标准

### P0：会议和员工录音

- Windows/macOS Tauri 可启动；员工不能用浏览器开会。
- 10 人会议稳定运行 60 分钟。
- 音频、视频、聊天和屏幕共享可用。
- 员工本地麦克风录音自动上传，可暂停，断网后可恢复；checksum 一致。
- 进会前全员完成录音确认。

### P1：嘉宾与服务端录制

- 内网嘉宾用链接+密码进会；无等候室。
- 组织者可锁定（此后员工和嘉宾都进不来）和踢人。
- 能保存独立音轨、房间混音、房间画面。
- 嘉宾无本地录音；员工缺轨时可 `local_fallback`，否则明确失败。

### P2：会后转写与纪要

- 普通参会人转写绑定显示名；嘉宾验证邮箱后合并身份。
- 普通话和至少一组粤语样本完成模型对比。
- 输出摘要、决策、待办和来源引用；待办负责人只能是内部用户或为空。
- 内部参会人可修订纪要；嘉宾只读。

### P3：知识库与企业接入

- 知识库问答走 Vespa，查询必带 ACL；能看即可下载，下载可审计。
- 员工登录对接现场已有身份（token 契约见技术栈文档）；本 PoC 不自建 IdP。
- 媒体/知识两套保留策略可配置。
- 管理员默认不能听会；破窗路径可演示。

## 11. 当前风险

1. **员工用浏览器逃避本地录音**：产品策略已定为拦截。实现上必须做稳定的「打开客户端」深链，并审计拦截事件。
2. **无等候室 + 可转发链接**：锁定、踢人、重置密码必须在第一版就可用，不能拖到「以后再做会中控制」。
3. **粤语模型质量**：必须用目标企业会议样本评估，不能依据普通话 benchmark 推断。
4. **模型许可证**：FunASR、WhisperX、pyannote、Qwen 等分别做商业审查；未授权权重不得进入交付包。
5. **嘉宾身份合并**：会中临时 ID 与会后邮箱验证的时序、重复邮箱、未验证就散会，需要明确的合并与展示规则。
6. **可选 DMZ**：证书、TURN、NAT、带宽是 v1 网络项目，不是 PoC 关门条件，但会显著影响交付。
7. **离线升级**：模型包体积、GPU 驱动和镜像签名会显著影响交付流程。

已降级、不再作为主路径风险：

- macOS 屏幕录制权限 / Windows WASAPI loopback：本地录音不录系统声，PoC 不测 loopback。
- 场外混音导入与电话接入：v1 不做。
