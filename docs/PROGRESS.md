## 结论

原先“约 95%”没有可复核的计算依据，并把 stub、配置草稿和未做真人/真实集群验证的代码计作完成，现已撤销。

按架构文档的 P0-P3 验收标准，当前四个阶段均未完整验收：P0/P1 有可运行 PoC 主干。P2 已补上结构化纪要、任务表、魔法链接、**无 SMTP 时的会中验证码**和跨会身份合并。P3 已有会外分享、破窗、双保留、回放、查看/离会/登录登出审计骨架，以及 **ACL-first YQL 检索（无 embedding）**。仍缺真实 IdP、Dapr Workflow、真实纪要 LLM、现场 SMTP 和真实 Vespa 集群验收。

状态定义：

- **已实现**：仓库内存在实际实现与自动化测试，不依赖假数据宣称业务完成。
- **部分实现**：主干存在，但缺少文档要求的分支、持久化、自动恢复或端到端验证。
- **仅 stub**：只能演示接口/状态流转，输出不是可交付业务结果。
- **外部未验证**：代码已接线，但没有所需服务、模型、平台或真人场景的验收证据。
- **未实现**：没有对应生产路径。

## 本轮修复

1. 统一会议级权限：陌生员工不能读取会议、聊天、媒体、转写、纪要或流水线，也不能上传本机录音/伪造活跃心跳。
2. 未受邀员工首次加入必须提供会议密码；锁定会议阻止所有新令牌签发。
3. 撤销“嘉宾自填邮箱即获得 ACL”的不安全实现；完成真实邮箱验证前不授予会后访问。
4. 破窗与审计接口按 `audit_admin` / `system_admin` 角色收紧。
5. 员工邮箱不再误命中嘉宾邮箱 ACL；索引写入错误不再被吞掉。
6. Worker 音源顺序修正为按人 `participant_track -> local_mic`，房间混音不再冒充正常转写音源；全场无权威音源时进入 `MANUAL_REVIEW`。
7. Tauri 本机录音改为入会前自动开始，离会/全员结束自动收尾上传；待传队列在桌面端启动/进会空闲时自动续传。
8. 房间密码从无盐 SHA-256 升级为 bcrypt，并兼容旧哈希校验。
9. 引入持久化会议成员模型，补齐内部邀请、共同组织者权限、受邀员工会议列表及无密码入会；未受邀员工仍需房间密码。
10. 嘉宾会后访问改为 SMTP 验证码闭环：未确认录音或未验证邮箱的嘉宾不能读产物/检索；验证成功后才写邮箱 ACL、重索引并签发会后令牌。
11. 纪要对齐架构 §6.3：决策/待办/风险带来源引用；待办负责人只能是内部用户；内部参会人可修订，嘉宾只读；AI 原稿与修订事件分开保存。
12. 转写会绑定入会显示名快照；独立音轨与本机备份带 `participant_key`。
13. 媒体下载在 MinIO/S3 可用时签发预签名 URL；知识索引覆盖纪要、决策、待办、转写和聊天窗口。
14. 多端观看：入会令牌可选 `device_id`，LiveKit identity 为 `user~device`；踢人与 `IsKicked` 都按去掉设备后缀的用户键，避免踢一端子账号或误踢组织者第二台设备。
15. 会中抢麦：后设置 `mic_floor_at` 的同账号设备成为麦克风源，前一端静音；员工 Tauri 只在当前发麦端继续本机录音。
16. 会外邮箱分享：组织者白名单 + 验证领取 + 取消分享后重索引；破窗补齐拒绝与撤销。
17. 空闲结束会先看 LiveKit 在房人数：有人则续命，查失败不结束。
18. 双保留时钟：媒体/画面/知识可分别配置；到期清对象标记、删转写纪要并删索引块。
19. 会后页在有预签名 URL 时内嵌音视频回放；待办可标完成并写修订/审计。
20. 会后任务表：结束会议入队；Worker 可 claim/complete/fail；超限死信进 `MANUAL_REVIEW`；组织者可重排队。
21. 嘉宾验证补魔法链接；验证后把临时说话人 ID 合并为 `email:地址`（含该邮箱出现过的其他会议）。
22. GET 转写/纪要/媒体记 `artifact_view`；离会记 `meeting_left`；首页可点选近期同事并发出邀请。
23. 无 SMTP 时组织者可出示会中验证码并复制魔法链接；添加会外分享也会返回码和链接。员工加载会议列表记 `employee_login`，首页可退出并记 `employee_logout`。人工复核接口附带死信任务。
24. Vespa Search 改为 ACL-first YQL（httptest 断言请求体；失败才退回本地副本）。会中嘉宾名单带入会显示名。转写/纪要下载会保存 JSON，并新增 `export` + `artifact_export`。语言字段用启发式填写，明确不是 FunASR。
